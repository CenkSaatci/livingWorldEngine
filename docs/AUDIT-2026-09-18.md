## 2. Kritisch

### K-1 Unbekannte `actionType` gelingt mit 0 Schaden statt Fehler [CRITICAL]
`CombatService.java` (executeAction): `COMBAT_ACTION_TYPE_INVALID` (400, so in `ERROR-CODES.md`/`API.md` dokumentiert) wird **nirgends geworfen** (0 Treffer im Code). Ein Tippfehler wie `"FIREBALL"` verbraucht AP, macht 0 Schaden und publiziert Erfolg. Fix: unbekannte `actionType` vor AP-Abzug mit `COMBAT_ACTION_TYPE_INVALID` ablehnen.

### K-2 Unbekannter Skill in 3W20-Probe ist immer erfolgreich [HIGH]
`ProbeService.java:225-242`: Skill nicht gefunden → 0 Attribute → 0 Würfe → `fails(0) <= Bonus` → `success=true`. Fix: unbekannter Skill → Fehler (wie Fail-closed-Prinzip), nicht Auto-Erfolg.

### K-3 Typisierte 404er fehlen an zwei Stellen → 500 statt 404 [HIGH]
`CharacterSheetService.java:64-68`, `ProbeService.java:106-111` werfen rohe `RuntimeException("ENTITY_NOT_FOUND"/"WORLD_NOT_FOUND")`; `GlobalExceptionHandler.java:82-90` kennt nur typisierte Codes → 500 `SYSTEM_INTERNAL_ERROR`. Fix: typisierte Exceptions wie überall sonst.

## 3. Hoch (Funktionalität & Rechte)

### H-1 Kampagnen-DM sieht nicht alles [HIGH]
Roster-/Listen-/Sheet-Filter privilegieren nur Welt-DM (`worldAccess.requireDm`), nie Kampagnen-DM. Bei Legacy-Kampagnen (kein Fork-Sync) sieht ein Leiter nur eigene PCs bzw. wird aus dem Roster geworfen — das bricht die ADR-Rolle „Leiter". Fix: `CampaignMemberService.isDm` in die Filter einbeziehen.

### H-2 Zwei Codes für denselben Fehler + Fate-Punkt verloren [HIGH]
`EntityService.java:399` (`CONDITION_UNKNOWN`) vs `:441` (`UNKNOWN_CONDITION`); Sozial-Effekte scheitern mit 400 + katalogfremdem Code — **nachdem** der Fate-Punkt bereits ausgegeben wurde (`ProbeService.java:174-178`, Spend vor Apply). Fix: Codes vereinheitlichen, Reihenfolge validieren→ausgeben oder Rückerstattung.

### H-3 Kind-Fehlgriff ist Upload-Blocker statt Warnung [MEDIUM→HIGH für Autoren]
`RuleSchemaValidator.java:380-388`: Die ADR verlangt ausdrücklich eine **Warnung**, implementiert ist ein harter Fehler. CoC-Beispiel passiert nur, weil seine Skills kein `kind` tragen. Fix: ADR *oder* Code angleichen (Empfehlung: Warn-Level einführen statt stillschweigend zu blocken).

### H-4 Case-Regeln uneinheitlich [HIGH für Content-Autoren]
Nur Formeln sind case-insensitiv; Skill-Lookup (`CombatService.java:966,973`, `ProbeService.java:126,139`), Conditions und Traits sind case-sensitiv (`"athletik"`→Skill 0/`UNRESOLVABLE`, `"wunde"`→kein Malus). `RULES-SCHEMA.md:115` behauptet sogar case-sensitiv — Widerspruch zur ADR. Fix: eine Regel überall + Doku angleichen.

### H-5 Rundung inkonsistent [MEDIUM]
`DerivedValueService.java:92` (`ceil`) vs `CombatService.java:1012` (`round`) vs `RestService.java:97` (`round`): 7,4 → Bogen 8, Kampfzielwert 7. Fix: eine Rundungskonvention + Test mit krummen Werten.

## 4. Mittel (Code-Qualität, gedeckt durch Stichproben)

- **Duplikate:** `parsePerCharacterSkills` (Probe-/Sheet-/CombatService), `selectedTraits`/`entityTraits` (4×), `parseAttributes` (3×), `loadSystemByCampaign`+Fallback (7+ Stellen), `resolveEngine`/`getEngineForWorld`, Backend-vs-Frontend (`skillAdvanceCost`, Trait-Matching). → je eine zentrale Stelle.
- **Fail-open-Catches:** `parseEffectsJson`→Schaden 0 + AP weg; korrupte Waffe→still `1d6`; kaputtes Regel-JSON→leere Map; `gridDistance`→0 umgeht `checkRange`; `modifierFormula`-Fehler→0.0 + Teilstring-`replace("name",…)`. → korrupt = Fehler ( fail-closed-Prinzip fortsetzen).
- **Tot/ungenutzt:** `CombatService.rollService` (Feld, 0 Lesezugriffe); Heilausdruck ungeprüft nach Teil-Writes; `useAbility` ohne Reichweiten-Check (toter `COMBAT_LINE_OF_SIGHT_BLOCKED`-Code wie `ACTION_TYPE_INVALID`).
- **Validierung an Boundaries:** `LocationController` (`parseInt` ohne try), `UUID.fromString` ohne Guard (Entity/Trade), `RestService`-%-Parsing, unchecked Casts (`skill.get("casting")` u. a. → 500 statt 400), `Pattern.compile` im Hot Path → `static final`.
- **Transaktionen/N+1:** `executeProbe` nicht-`@Transactional` trotz Schreibeffekten; `getParticipants`/`involved`/per-Entity-`loadSystem` laden je Teilnehmer; Single-Load-Ansatz aus `executeAction:160` überall anwenden.
- **API-Konsistenz:** `LAST_DM`→409 vs `DM_REMOVAL_DENIED`→403 (eine Invariante); Response-Wildwuchs (DTOs vs `ApiResponse("Text")` vs rohe Maps); drei Paginierungs-Konventionen.
- **Migration V106** korrekt (Backfill deterministisch via `joined_at NOT NULL`), aber kein Constraint „Creator muss DM sein" — als Follow-up-Doku vermerkt.

## 5. UI/UX (Top-Funde)

1. **Kampf-Blindflug:** Kein Treffer/MISS/Schaden-Feedback, Sound immer, Fehler nur `Action failed`; Buttons ohne Grund disabled, kein Pending (Doppel-Submit). → Server-Resultat als Toast/Badge, `AP n` ans Button, `acting`-Lock.
2. **Wizard:** Save ignoriert `forceRename`/`bumpVersion` (nur JSON-Editor hat sie); nur 1. Issue als Toast ohne Feld-Markierung/Step-Sprung; `Weiter` immer aktiv; Skill-Zeile läuft mobil über; `kind` Freitext ohne Hint; hartcodierte deutsche Strings.
3. **i18n-Lücken:** `GameSystemPage`, `CharacterSheet` (Save-Fehler), `ActionBar`, `InitiativeList`, `QuestDetailPage` (komplett englisch, kein Error-State), Adventure/Chat-Hartcodes; neue ADR-014-Keys sind vollständig in allen 6 Locales. i18n-Init blitzt EN vor DE.
4. **A11y:** Icon-only-Buttons ohne `aria-label` (Wizard-X, Sheet-Check/X, Chat-Send, Combat-Back, DiceModal-X, ProbeRoller-Würfel); Probe-Popup ohne Backdrop/`role=dialog`; Escape/Confirms lückenhaft; Toasts überdecken mobil die ActionBar.
5. **Kleinigkeiten:** Trade ohne Erfolgs-Toast; Fate-Doppel-UI; `probeType`-Rohstring + Sprachmix im Popup; Creator-Transfer ohne Confirm; Rollenwechsel ohne Refetch; `pullSystem` ohne Toast/Loading; Skill-/Attribut-Tooltips nur Hover (`title`).

## 6. Vision-Urteil: intakt mit drei Drifts

- **Intakt:** keine Systemnamen/Verzweigungen in Engine-Pfaden (einziger Fall: Adventure-Fallback `asText("staerke")` — ersetzen); Deferred Items sauber abwesend; D&D/CoC/DSA-Beispiele validieren.
- **Drift 1:** Bot-ATTACK würfelt fix `1d6` an der ADR-014-Pipeline vorbei (`IntentExecutor.java:99-100`).
- **Drift 2:** Case-Sensitivität (s. H-4) — ADR verlangt einheitlich.
- **Drift 3:** kind-Hard-Error vs ADR-Warnung (s. H-3).
- **Doku-Drift:** doppelte `combat.damage`-Zeile mit Widerspruch, tote Codes im Katalog, `INVALID_ROLE`/`LAST_DM`/`WORLD_MISMATCH` fehlen, `USER-GUIDE.md` kennt Ersteller-Modell/`forTrade`/Fehlerdarstellung nicht, `TASKS.md`-Kopf veraltet.
- **Risiken:** Regel-JSON-Komplexität wandert zu Autoren (Wizard hilft zu wenig); Single-Creator ohne Austrittszwang kann Runden führungslos verriegeln.
