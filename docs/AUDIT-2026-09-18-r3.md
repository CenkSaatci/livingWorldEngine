## 3. Neue Findings (R3)

### N-1 [MEDIUM] Heilung bleibt im Kampf unsichtbar (Kontrakt-Lücke)
`CombatService.useAbility` liefert nur `damage`/`RollBreakdown`, kein Heil-Feld; `CombatController.ActionResultResponse` kennt ebenfalls keins. `ActionBar` zeigt deshalb bei einer Heil-Fähigkeit „Aktion ausgeführt", obwohl HP wiederhergestellt wurden (`CombatService.java:321-322`, `CombatController.java:148-153`).
**Fix:** `heal`-Feld (Analog zu `damage`) in `CombatActionResult` + DTO, Toast „heilt X".

### N-2 [LOW] `DamageExpression`-Kanten (Block C)
- `1d6+9999999999` → `NumberFormatException` statt `null` (Vertrag: null bei unparsbar).
- `1d6+2147483647+1` → stiller Integer-Wrap (negativ).
- Spaces verschmelzen Identifier: `1d6 + staerke mut` → Attribut `"staerkemut"`.
- `1D6+2` wird abgelehnt, `DiceExpression` akzeptiert `1D6` (case-inkonsistent, lowercase dokumentiert).
**Fix:** Zahl-Guard + `catch (NumberFormatException) → null`, optional `CASE_INSENSITIVE`.

### N-3 [LOW] B7/B8 ohne Regressions-Tests
Für Case-Cap-Pfad, `nextTurn` in ENDED, `ABILITY_NOT_FOUND`/`COMBAT_EFFECTS_INVALID`-Mapping und negativen `attrBonusSign` existiert kein Test — der laut Audit riskanteste Teil (H-4/H-6). Je 1 kleiner Test reicht.

### N-4 [INFO] Aufräum-Kandidaten
`EntityService.updateProgression` (ungenutzt, ignoriert `level`), `CombatController.CombatActionResultResponse:134` (toter Record), `GlobalExceptionHandler:115` (zwei cases pro Zeile).
