## 2. Kritisch

### CR-1 ActionBar-Crash: Hook nach Early-Return — **Regression aus `9ea7a19`**
`frontend/src/components/combat/ActionBar.tsx:134` (Early Return bei `!session`) vs. `:140` (`useState(acting)`) verletzt die Rules of Hooks. Sobald `session` von null auf aktiv wechselt (Deep-Link/Reload in laufenden Kampf, Kampfstart), wirft React „Rendered more hooks than during the previous render" und die ErrorBoundary ersetzt die ganze App. Verifiziert (extern reproduziert; ESLint `react-hooks/rules-of-hooks`).
**Fix:** `acting`-State vor den Early Return ziehen (1 Zeile).

## 3. Hoch

### H-1 Manöver & Fähigkeiten verlieren ihr Ergebnis — **Regression aus `50e8c96`**
`CombatController.java:49-58` (`/maneuver`) und `:95-105` (`/ability`) rufen den Service, verwerfen aber `CombatActionResult` und nutzen den 2-Arg-Konstruktor (`result=null`). `ActionBar` liest `res.data.result` → verfehltes Manöver zeigt „Aktion ausgeführt" + Treffersound, Ability-Schaden/-Heilung bleibt unsichtbar. `docs/API.md:468` behauptet das Gegenteil.
**Fix:** In beiden Methoden `ActionResultResponse.from(result)` an den Response-Konstruktor geben.

### H-2 Schadensparser widerspricht der Doku + schluckt Minus
`DamageExpression.java:25-32`: `1d8+staerke+2` (`RULES-SCHEMA.md:88`) und `1d8 + stärke` (`API.md:126`) sind nicht parsbar → zur Laufzeit `COMBAT_ATTACK_UNRESOLVABLE` (422) für dokumentierten Content. `1d6-staerke` matcht das ATTR-Muster mit `-`, wirft das Vorzeichen aber weg → Bonus wird addiert statt subtrahiert.
**Fix:** Parser um Spaces/Mehrfachterme/Vorzeichen erweitern; Validator prüft `combat.damage` beim Upload.

### H-3 `forTrade` leakt komplette Charakterdaten (Vision)
`EntityService.java:160` lässt bei `forTrade=true` alle PCs durch; `EntityController.java:43-52` mappt sie mit `EntityResponse` inkl. `attributesJson`, `inventoryJson`, `metadataJson`, `backstory`, HP/AP. ADR-014 und `API.md:320` versprechen „Sheets bleiben zu" — der Endpoint liefert sie aber allen Weltmitgliedern.
**Fix:** Eigenes schlankes DTO (`id`, `name`, `entityType`) für die Trade-Liste.

### H-4 K-3-Lücke: `updateProgression` → 500 statt 404
`CharacterSheetService.java:222-223` wirft rohes `RuntimeException("ENTITY_NOT_FOUND")`; `GlobalExceptionHandler.java:82-90` kennt nur typisierte Codes → 500 `SYSTEM_INTERNAL_ERROR`.
**Fix:** `EntityException` wie in `getSheet`.

### H-5 Adventure neutralisiert K-2: jeder Probe-Fehler wird Story-Fehlschlag
`AdventureService.java:242-244` (`catch (Exception e) { skillCheckSuccess = false; }`): der neue Fail-closed-Fehler `ROLL_SKILL_NOT_FOUND` (und jeder Infrastrukturfehler) wird still zum „Wurf misslungen" und die Story läuft auf den Failure-Node.
**Fix:** `ProbeException`/`SocialException` von echten Wurffehlern unterscheiden, loggen und rethrown; nur gültige Wurfergebnisse werten.

### H-6 Skill-Cap per Groß-/Kleinschreibung umgehbar (H-4-Rest)
`EntityService.java:322-324`: `e.getKey().equals(d.get("name"))` findet die Skill-Definition bei „ATHLETIK" nicht → `continue`, nur `maxSkillValue` greift → die Attribut+2-Regel ist umgehbar (`PATCH {"ATHLETIK": 99}`).
**Fix:** `RuleNames.eq` (und Kollisionsfälle wie `RuleNames.get`-Mehrdeutigkeit dokumentieren).

### H-7 Wizard speichert an `forceRename`/`bumpVersion` vorbei (Altfund, unverändert)
`SystemWizard.tsx:74-109` PATCH ohne Flags; Checkbox/Duplikat-Confirm existieren nur im JSON-Editor. Backend defaultet `bumpVersion=true` → Wizard bumpt immer; Duplikatname endet als generischer Fehler.
**Fix:** Save über die Page-Handler delegieren oder Flags durchreichen.

### H-8 Wizard-Validierung rendert Müll
`SystemWizard.tsx:76-80` toastet nur `issues[0]`; `types/gameSystem.ts:777-784` erzeugt Keys wie `v_pkg_name:0` → i18next deutet `:` als Namespace-Separator und rendert nur „0"; `v_pkg_*`/`v_empty_condition_name` fehlen in allen Locales; kein Step-Sprung/Feld-Highlight.
**Fix:** Issues strukturiert (`{key, step, field}`) zurückgeben, Liste rendern.

### H-9 GameSystemPage durchgehend englisch
Toasts, Buttons (`Load Template`, `Validate`, `Save System`), Delete-Dialog (`:188-:825`). Dazu: Warnungen nur als `title`-Tooltip (auf Touch unlesbar), Fehler nur `errors[0]`.
**Fix:** `systems.*`-Keys + aufklappbare Fehler-/Warnliste.

### H-10 i18n-Init deaktiviert die Spracherkennung
`frontend/src/i18n/index.ts:81` setzt `lng: FALLBACK_LOCALE` → der LanguageDetector wird nie aufgerufen; gespeicherte Locale wirkt nicht beim Boot, anonyme Erstbesucher sehen EN.
**Fix:** `lng` weglassen bzw. gespeicherte Locale vor dem Render setzen.

### H-11 Lint-Gate rot
`npm run check` scheitert mit 46 Errors/13 Warnungen (u. a. Rules-of-Hooks aus CR-1, `no-explicit-any` in `gameSystem.ts`). Das Gate ist damit wertlos.
**Fix:** CR-1 + Restfehler beheben oder Gate bis dahin aus der Definition of Done nehmen.

## 5. Vision-Urteil

**Driftend, Kern intakt.** Formeln/Skill-Variablen, Case-Zentralisierung (bis auf Reste), Rundung, Fail-closed an den Kernpfaden, Leiter-Sichtbarkeit und Chat-Sender sind sauber umgesetzt und getestet. Die drei größten Risiken: (1) `forTrade` liefert fremde Komplett-Charaktere, (2) Anzeige-/Chat-/Wetter-Texte sitzen hart deutsch im Backend und brechen i18n/Systemagnostik, (3) Fail-open-Reste (Regel-JSON, Waffen-/Verteidigungs-Metadata, Engine-Fallback) und die duplizierte NPC-Schadenspipeline unterlaufen „kaputt = Fehler" und „eine Pipeline".
